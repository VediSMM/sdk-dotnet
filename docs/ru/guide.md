# Руководство по VediSMM SDK для .NET

## Жизненный цикл клиента и аутентификация

Создавайте один фасад `VediSmm` на время жизни приложения. Конструктор с настройками создаёт собственный `SocketsHttpHandler` с запрещёнными перенаправлениями и владеет пулом соединений. Конструктор с готовым `VediSmmClient` заимствует клиент, поэтому освобождение фасада не уничтожает состояние вызывающей стороны.

`AccessToken` хранит фиксированный токен только в памяти, а `TokenProvider` получает актуальный токен непосредственно перед защищённым запросом. Эти параметры взаимоисключающие. Провайдер получает тот же конечный токен отмены, что и HTTP-обмен.

## Вызовы и отмена

Каждая доменная операция возвращает `Task<ApiResponse>` и принимает `CancellationToken`:

```csharp
var options = new CallOptions
{
    Query = new Dictionary<string, IReadOnlyList<string>>
    {
        ["from"] = new[] { "2026-07-01" },
        ["to"] = new[] { "2026-07-19" },
    },
};
ApiResponse summary = await sdk.Analytics.GetAnalyticsSummaryAsync(options, cancellationToken);
```

Значения пути и query кодируются SDK — предварительно кодировать их не нужно. Имена и значения заголовков проверяются от инъекций, а чувствительные заголовки остаются под управлением SDK.

## Ошибки

Неуспешный HTTP-ответ никогда не маскируется под нормальный результат:

- `ApiException` сохраняет статус, стабильный код, очищенное описание, ошибки валидации, ID запроса и `Retry-After`;
- `RateLimitException` соответствует HTTP 429;
- `PreconditionFailedException` соответствует HTTP 412;
- `RedirectException`, `RequestTimeoutException`, `TransportException` и `DecodeException` различаются;
- отмена вызывающей стороны остаётся `OperationCanceledException`.

Размер тел ошибок и успешного JSON ограничен. Если сервер отразит токен в Problem Details, SDK удалит его из всех доступных полей.

## Идемпотентность и оптимистичная блокировка

```csharp
var command = new CallOptions
{
    Path = new Dictionary<string, string> { ["id"] = "42" },
    IdempotencyKey = Idempotency.NewKey(),
    IfMatch = "\"post-v7\"",
    JsonBody = new { version = 7 },
};
ApiResponse job = await sdk.Jobs.PublishPostAsync(command, cancellationToken);
```

SDK фиксирует повторяемые JSON/raw-тела и сохраняет один ключ идемпотентности при ограниченных повторах. Изменяющий запрос без гарантии идемпотентности повторно не отправляется.

## Курсорная пагинация

`CursorPager<T>` загружает страницы лениво, передаёт callback только непрозрачный предыдущий курсор, выявляет пустые и повторные курсоры и распространяет отмену. Модель ответа остаётся под контролем приложения.

## Потоковая передача медиа

`ContentFactory` создаёт новый `HttpContent` для каждой допустимой попытки загрузки. `ResponseStream` направляет успешное скачивание в поток вызывающей стороны; SDK пишет в поток, но не освобождает его.

## Задания публикации

`JobWaiter` использует монотонный конечный таймаут и отменяемый интервал опроса. Он возвращает успешное представление, выдаёт `JobFailedException` для неуспешного/отменённого задания и не запускает фоновых опросчиков.

## Вебхуки

Передавайте точные исходные байты запроса, заголовок времени и подпись `v1=` в `WebhookVerifier.VerifyAsync`. Проверка включает допуск времени, HMAC-SHA256, сравнение за постоянное время и необязательную атомарную защиту от повторов. `MemoryReplayStore` безопасен в одном процессе; распределённая система должна реализовать `IReplayStore` поверх общего атомарного хранилища.
